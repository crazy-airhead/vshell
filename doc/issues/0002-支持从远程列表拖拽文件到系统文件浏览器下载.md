# ISSUE-0002 — 支持从远程列表拖拽文件到系统文件浏览器下载

> **编号**：0002　**状态**：⚪ 不修复（保持现状，待 Wails v3 后续支持）　**严重程度**：⚠️ 一般（能力缺失，受框架/平台限制，实现难度高于 0001）
> **发现日期**：2026-07-10　**相关任务**：SFTP / 文件传输

## 问题描述

把 SFTP 面板「远程」文件列表中的文件**直接拖出窗口**，落到系统文件浏览器（macOS Finder）或桌面，即触发下载到该位置——与 0001（拖入上传）形成对称的拖拽传输交互。

当前该交互不存在：远程行只能拖向应用内的「本地」列表区域完成下载（应用内拖拽），无法拖出到系统 Finder。

## 复现步骤

1. 连接一台 SSH 服务器，打开其 SFTP 面板。
2. 在远程列表选中一个文件，按住拖向窗口外（Finder / 桌面）。
3. 松开鼠标。

## 期望行为

拖出窗口落到 Finder/桌面时，文件下载到该目标目录（或系统下载目录），传输进度通过 `sftp:progress` 事件展示。

## 实际行为

拖出窗口无系统级拖放反馈，松开后不触发任何下载。现有应用内「远程→本地列表」拖拽仍可用（指针事件机制 + `handleLocalDrop` → `SFTPDownload`），但那是落到应用内本地列表区，不是落到系统 Finder。

## 影响范围

- SFTP 下载的对称拖拽交互缺失。
- 受 webview 沙箱限制：浏览器 JS 无法把远程文件直接表现为可拖出的本地文件，「拖出」必须依赖原生层支持（主动发起系统级拖放，如 Electron 的 `webContents.startDrag`）。这是本功能与 0001（被动接收拖入）本质不同、也更难的原因。
- 替代路径：应用内 remote→local 拖拽、下载按钮、双击下载。

## 相关文件 / 符号

- `frontend/src/components/sftp/SFTPPanel.vue`
  - `onRemoteRowPointerDown`（L71）`useDragSource({ source: 'remote' })` —— 现仅作为**应用内**拖拽源（pointer 事件），不产生系统级拖放。
  - `handleLocalDrop`（L488）/ `handleDownload`（L470）—— 应用内下载入口，调 `SFTPDownload`。
- `main.go` —— 仅有拖入处理（`EnableFileDrop` + `WindowFilesDropped`，见 0001），**无任何「拖出」处理**。
- `internal/app/app.go`（SFTP）—— `SFTPDownload` 下载能力本身已具备，缺的是「触发下载到拖放目标目录」的编排。
- `frontend/src/composables/useDragTransfer.ts` —— 基于指针事件的自定义拖拽，无法承载系统级 drag-out。

## 调研结论（2026-07-10，基于 Wails v3 `alpha2.117` 源码）

**Wails v3 不提供文件拖出（drag-out 到系统文件管理器）的能力。** 已将框架升至最新 `alpha2.117` 后，逐项核对模块源码：

- 源码中确有 `startDrag()`（`pkg/application/webview_window.go:1479`，macOS 实现调 `[windowDelegate startDrag:nsWindow]`），但它由前端消息 `"wails:drag"` 触发、与 `"wails:resize:"` 并列——是**无边框窗口的「移动窗口」**机制，与文件拖出无关。
- 其余拖放代码均为**拖入**：`handleDragAndDropMessage` / `dragAndDropMessage` / `windowDragAndDropBuffer`（接收外部文件）、`WindowFileDragging{Entered,Exited,Performed}`（macOS 拖入悬停跟踪）。无任何「发起系统级文件拖放」的符号。
- 与官方/社区一致：drag-out 由 GitHub issue [#4648](https://github.com/wailsapp/wails/issues/4648)（maintainer 明确「v3 支持拖入，拖出尚未支持」）、[#3158](https://github.com/wailsapp/wails/issues/3158) 追踪，至今未实现。`startDrag`（拖出文件）是 Electron 的概念，Wails 无对应物。

> 附注（Windows 端）：alpha.36+ 曾有拖放回归（issue #4701，Windows-only）；本项目以 macOS 为主，不受影响，但跨平台时需留意。

## 建议方案

既然原生 drag-out 不可得，按可行性排序：

1. **降级 A（推荐，低成本）**：把「拖出」语义改为——远程文件拖到应用外/松手时，`SFTPDownload` 到「当前本地列表目录」或系统下载目录，完成后 `OpenInFileManager` 定位。交互上接近拖出，但实际是「拖出即下载到本地并打开」。`SFTPDownload`、`OpenInFileManager` 后端均已具备，主要是前端拖拽边界判断 + 编排。
2. **降级 B（零成本）**：维持现有应用内 remote→local 拖拽 + 「在 Finder 中打开」作为可用替代，不做额外开发。
3. **原生实现（高成本，不推荐当前阶段）**：自行写平台原生拖出（macOS `NSDraggingSource` + `NSPasteboard`、Windows OLE drop-source、Linux GTK DnD source），经 Wails 绑定桥接。工作量大、跨平台维护负担重，且与框架后续可能的原生支持（#4648）冲突。建议等官方支持或仅做 macOS 单平台。
4. **官方跟进**：订阅 #4648，待上游实现后接入。

> 注意：0001（拖入）是 Wails `WindowFilesDropped` 被动接收；0002（拖出）受框架限制无法用同样机制，方向相反、本质不同。当前结论：**原生拖出不可行，建议走降级 A**。
