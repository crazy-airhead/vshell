# ISSUE-0007 — 删除已被 SSH 连接使用的私钥无任何拦截

> **编号**：0007　**状态**：🟢 已修复　**严重程度**：⚠️ 一般（误删导致连接与密钥管理状态漂移）
> **发现日期**：2026-09-02　**相关任务**：密钥管理 / 连接管理

## 问题描述

密钥管理面板里删除一个**正被连接使用**的私钥，直接删除成功、无任何提示。虽然连接保存的是私钥的加密副本（删文件不影响已有连接登录），但删除后：`key_name` 关联悬空（编辑表单预选失效，见 0005 第 2 轮）、密钥管理里也没了这把钥匙，用户会误以为连接「没在用它」或排查认证问题时无从对证。期望：删除时检测占用并提示「已被使用，不能删除」。

## 复现步骤

1. 新建连接，私钥认证，从密钥管理选择某密钥（或手动粘贴同一把密钥的内容），保存。
2. 打开密钥管理 → 该密钥悬停 → 删除 → 确认。
3. 观察：密钥直接被删，无占用提示。

## 期望行为

- 删除被连接使用的密钥时，提示「密钥 "xxx" 正被以下连接使用：…，无法删除」，拒绝删除。

## 实际行为

- 直接删除成功，无提示。

## 影响范围

- 密钥管理删除入口（悬停按钮 + 右键菜单共用 `handleDelete`）。
- 判定「被使用」需覆盖两类数据：`key_name` 关联（0005 第 2 轮起）与**私钥内容一致**（存量连接、手动粘贴同一把密钥、SSH 配置导入的旧数据）。

## 相关文件 / 符号

- `internal/app/app.go` — `DeleteSSHKey(name)`（原逻辑直接删文件，无占用检查）。
- `frontend/src/components/keys/KeyManagementPanel.vue` — `handleDelete(key)`（直接调 `store.deleteKey`）。
- `frontend/src/stores/sshkey.ts` — `deleteKey`。

## 建议方案（可选）

1. 后端新增 `GetSSHKeyUsage(name) ([]string, error)`：读密钥文件内容，遍历连接——`key_name` 命中，或解密后的 `private_key` 内容（trim 比较）与文件一致，即视为使用中，返回连接名列表。
2. `DeleteSSHKey` 内部先做同样检查，有占用则返回错误（后端兜底，防未来调用方绕过前端）。
3. 前端 `handleDelete` 先查占用：非空则 toast i18n 提示（列出连接名）并中止，不再调用删除。
