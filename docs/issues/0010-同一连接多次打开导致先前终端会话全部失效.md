# ISSUE-0010 — 同一连接多次打开导致先前终端会话全部失效

> **编号**：0010　**状态**：🟡 进行中（待实机验收）　**严重程度**：⚠️ 一般
> **发现日期**：2026-10-07　**相关任务**：终端 / SSH 连接管理

## 问题描述

对同一连接反复「打开」（多开终端标签）时，开到一定次数后，之前打开的所有终端会话**同时**断开（显示已断开提示），只有最后新开的那一个可用。

## 复现步骤

1. 连接任意标准 sshd（OpenSSH 默认配置，`MaxSessions = 10`）。
2. 反复打开同一连接，累计开满 10 个终端标签。
3. 再开第 11 个；若该连接的 SFTP 面板已打开（占用 1 个 subsystem 会话），则第 10 个即触发。
4. 观察：前面 10 个终端全部显示「已断开」，仅新标签正常。

## 期望行为

超过服务端会话数上限时：仅新的一次打开失败，并明确提示原因（服务端 MaxSessions 限制）；已打开的终端不受任何影响，共享连接保持存活。

## 实际行为

新打开在内部先把共享 SSH 连接关闭并重拨（旧实现把一切 `newSession` 失败都当作「连接已死」），重拨成功后新标签正常——但旧连接被关闭导致其上所有终端会话被服务端断开，全部失效。

## 影响范围

所有 SSH 终端多标签场景。触发次数取决于服务端 sshd_config 的 `MaxSessions`：

- OpenSSH 默认 `MaxSessions = 10`（限制单条 TCP 连接上的 shell / login / subsystem 会话通道数；每个终端标签占 1 个 shell 通道，SFTP 面板占 1 个 subsystem 通道，监控采样是临时 exec 通道、不占常驻额度）。
- 默认配置 + SFTP 未打开：第 **11** 次打开触发；SFTP 已打开：第 **10** 次。

## 相关文件 / 符号

- `internal/ssh/client.go` — `Manager.Connect` 失败分支（原无条件 `evictClient` 关闭共享连接）
- `internal/ssh/client.go` — 新增 `isConnLevelError` / `friendlySessionError`
- `internal/ssh/client_test.go` — 新增回归测试（进程内 SSH server 模拟 MaxSessions 拒绝与握手后断连）

## 根因

同一连接的所有终端复用一个 `ssh.Client`（SSH 多路复用）。服务端按 `MaxSessions` 限制单条连接上的会话通道总数，超限时 `client.NewSession()` 被服务端拒绝（`administratively prohibited`）。旧实现不区分错误类别，把这种「服务端拒绝新会话」误判为「缓存的 client 已死」，走驱逐重拨路径：`evictClient` 关闭共享连接 → 前面所有终端随连接死亡；重拨的新连接只承载新标签。

## 方案（最终设计速查）

在 `Connect` 的 `newSession` 失败分支按错误类别分流：

- **连接级错误**（EOF / reset / 断开 / 传输层死亡，含 `unexpected packet in response to channel open: <nil>`，即 open 在途时连接死亡）：保留原「驱逐重拨」自愈逻辑（服务端空闲断开后的无缝重连）。
- **服务端拒绝新会话**（`administratively prohibited` / `resource shortage`）：不驱逐、不重拨，直接返回带 MaxSessions 提示的错误，由前端连接失败弹窗告知用户。
