# ISSUE-0004 — 终端内容区右键菜单缺失，复制粘贴无实现（疑似只能靠系统快捷键）

> **编号**：0004　**状态**：🟢 已修复　**严重程度**：⚠️ 一般（终端日常核心交互，但不阻断使用）
> **发现日期**：2026-07-20　**相关任务**：终端 / 交互

## 问题描述

在终端内容区域（xterm 容器）上右键，**没有任何右键菜单**弹出；复制、粘贴在代码里**完全没有实现**（无选区复制、无剪贴板粘贴）。用户反馈「右键菜单有时无法激活」，并怀疑「复制粘贴是不是只能用快捷键」。

经排查：右键菜单不是「有时无法激活」，而是**终端内容区压根没有绑定右键菜单**——只有标签页标题（tab 条）上有右键菜单。复制粘贴则连快捷键处理都没写，当前完全依赖系统/浏览器默认行为。

## 复现步骤

1. 连接一台 SSH 服务器，打开终端标签页。
2. 在**终端内容区**（黑色输出区域）点右键。
3. 观察：无任何菜单弹出（标签页标题上右键才有菜单）。
4. 选中一段终端输出，按 `Cmd/Ctrl+C` 或尝试粘贴 `Cmd/Ctrl+V`。
5. 观察：复制/粘贴行为不可靠（xterm 默认会拦截按键，且代码未实现）。

## 期望行为

- 终端内容区右键弹出上下文菜单（复制 / 粘贴 / 全选 / 清屏 等）。
- 选中文本可直接复制到系统剪贴板；粘贴可把系统剪贴板内容写入远端 PTY。
- 至少有一套稳定可用的复制粘贴途径（右键菜单 或 显式快捷键）。

## 实际行为

- 终端内容区右键：无菜单。
- 复制粘贴：代码未实现，仅靠系统默认行为，体验不可靠。

## 影响范围

- 终端日常使用最高频的两类操作（复制输出 / 粘贴命令）。
- 影响所有 SSH 终端会话，是核心交互体验缺失。

## 建议方案（可选）

两个问题同源（终端区域没有任何自定义交互），建议一并处理：

1. **终端内容区右键菜单**：在 `XTerminal.vue` 的 `.xterminal-container` 上绑 `@contextmenu.prevent`，用 Naive UI `NDropdown`（`trigger="manual"` + `x/y`，参考 `TerminalPane.vue` 现有写法）弹出菜单；菜单项按选区状态动态显示（有选区→「复制」、剪贴板非空→「粘贴」、再加「全选」「清屏」）。
2. **复制粘贴实现**：
   - 复制：`term.hasSelection()` / `term.getSelection()` → `navigator.clipboard.writeText()`。
   - 粘贴：`navigator.clipboard.readText()` → `term.paste(data)`（注意粘贴大文本的安全提示，可选）。
3. **快捷键兜底**：在 `useShortcuts.ts` 的 `ShortcutMap` 增加 `copy` / `paste`（如 `Cmd/Ctrl+Shift+C`、`Cmd/Ctrl+Shift+V`），并在 `settings.ts` 给默认值；终端聚焦时由 `attachCustomKeyEventHandler` 拦截处理，避免与 xterm 默认行为冲突。
4. **可选**：启用 `rightClickSelectsWord: true`，让右键自动选中光标下单词，再弹菜单。

> 注意 Wails v3 webview 中 `navigator.clipboard` 的可用性需实测；若不可用，可走后端绑定读写系统剪贴板（需新增 service 方法）。

## 解决记录

**第 1 轮**（2026-09-02）

- **处理**（按「建议方案」1–4 全部落地）：
  - `frontend/src/components/terminal/XTerminal.vue` —
    - `.xterminal-container` 绑定 `@contextmenu`，`NDropdown trigger="manual"`（参考 `TerminalPane.vue` 写法）弹出菜单：复制（无选区时禁用）/ 粘贴 / 全选 / 清屏；
    - Terminal options 增加 `rightClickSelectsWord: true`（xterm 自带的 contextmenu 处理先于容器 handler 执行：无选区时自动选中光标下单词，点击已有选区内则保留原选区，所以打开菜单时「复制」基本总是可用）；
    - 复制：`term.hasSelection()` / `getSelection()` → 写系统剪贴板；粘贴：读系统剪贴板 → `term.paste()`；清屏：`term.clear()`；
    - 剪贴板读写优先走 Wails 运行时 `Clipboard.SetText/Text`（WKWebView 下 `navigator.clipboard.readText` 不可靠），失败回退 `navigator.clipboard`，两层都失败静默降级；
    - `attachCustomKeyEventHandler` 拦截可配置的 copy/paste 快捷键（返回 `false` 阻止 xterm 把键发给 PTY，如避免 Ctrl+Shift+C 误发 `^C`）；另按 macOS 惯例：纯 `Cmd+C` 且有选区时复制。**未拦截**纯 `Cmd+V`——WKWebView 菜单加速键会走原生 paste 事件（xterm textarea 自带 paste 监听），手动拦截恐致双重粘贴，原生路径不可用时仍有右键粘贴与 `Cmd/Ctrl+Shift+V` 兜底。
  - `frontend/src/composables/useShortcuts.ts` — 导出 `matchesShortcut(e, combo)`（含 `parseCombo`），全局 keydown 处理器复用；供 xterm `attachCustomKeyEventHandler` 使用（全局处理器会跳过 xterm 隐藏 textarea 上的事件，故终端内需单独拦截）。
  - `frontend/src/stores/settings.ts` — `ShortcutMap` 增加 `copy` / `paste`，默认 `CommandOrControl+Shift+C` / `CommandOrControl+Shift+V`；加载时与 `defaultShortcuts` 合并，保证老用户已保存的快捷键表也能拿到新增键。
  - `frontend/src/components/settings/SettingsModal.vue` — 快捷键设置列表新增「复制（终端）/ 粘贴（终端）」两项。
  - `frontend/src/locales/zh-CN.ts` / `en.ts` — 新增 `terminal.copy/paste/selectAll/clear` 与 `settings.shortcutCopy/shortcutPaste`。
  - `frontend/src/wails-runtime.d.ts` — 本地 shim 遮蔽了 `@wailsio/runtime` 真实类型（同文件先例：`App.vue` 的 `Window` 靠 `@ts-ignore`），补充 `Clipboard.SetText/Text` 类型声明。
- **校验**：`pnpm typecheck` 0 错；`go build ./...` 通过（未改 Go 代码）；`pnpm build` 通过。
- **验收**（实机通过，2026-09-02 用户确认）：
  1. 终端内容区右键 → 弹出菜单，无选区时点在单词上右键自动选中该词且「复制」可用；

**第 2 轮**（2026-09-02）

- **反馈 / 触发**：用户问「复制、粘贴需要 Shift 合理么」——macOS 上 `Cmd+Shift+C/V` 不符合原生习惯。
- **根因**：第 1 轮默认值沿用了 Linux/Windows 终端惯例（`Ctrl+Shift+C/V`，因 `Ctrl+C` 是 SIGINT 不能抢），未按平台区分；mac 的原生惯例应为 `Cmd+C/V`。
- **处理**：
  - `frontend/src/stores/settings.ts` — 默认值平台感知：mac 为 `CommandOrControl+C` / `CommandOrControl+V`，其他平台维持 `CommandOrControl+Shift+C` / `CommandOrControl+Shift+V`（终端标准）。
  - `frontend/src/components/terminal/XTerminal.vue` — 拦截逻辑两处配套修正：
    - `CommandOrControl` 在 `parseCombo` 里匹配 `meta||ctrl`，mac 上若不排除会把纯 `Ctrl+C`（SIGINT）、`Ctrl+V`（quoted-insert）吞掉——终端内这两个快捷键在 mac 上仅匹配 Cmd；
    - 拦截时先 `event.preventDefault()`：粘贴场景下 WKWebView 菜单加速键路径可能再补发原生 paste 事件（xterm textarea 自带监听），不阻止会双重粘贴。
- **校验**：`pnpm typecheck` 0 错。
- **遗留**：无。实机验收通过（2026-09-02 用户确认）：mac `Cmd+V` 仅粘贴一次、`Ctrl+C` 仍可中断远端进程，第 1 轮验收清单各项均通过。
