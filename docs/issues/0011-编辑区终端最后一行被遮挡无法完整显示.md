# ISSUE-0011 — 编辑区终端最后一行被底部边缘遮挡，无法显示完整内容

> **编号**：0011　**状态**：🟢 已修复（2026-10-09 实机验收通过）　**严重程度**：⚠️ 一般
> **发现日期**：2026-10-09　**相关任务**：终端 / 岛屿布局（中心岛）

## 问题描述

用户反馈原话：「会话在编辑区域最后一行被遮挡，无法显示完整内容。」（登记时「会话」曾误记为「关闭」，已更正。）

截图（用户红框标注）：终端会话 `[dev]172.18.22.23` 的最后一行提示符 `[root@localhost ficus-catl-oa]#` 只露出上半部分，约半行被编辑区（中心岛）底部边缘裁切。

## 复现步骤

1. 打开 SSH 终端会话（截图环境：`[dev]172.18.22.23`）。
2. 观察到最后一行（提示符行）只显示上半部分，被编辑区底缘遮挡。

> 精确触发条件**待确认**：是会话打开即遮挡，还是底部工具窗开关、分隔条拖动、窗口缩放等高度变化后出现——排查时先区分。

## 期望行为

- 无论中心岛高度如何变化，fit 之后所有 PTY 行都完整可见；行数按可视高度向下取整，最后一行不被裁切（高度不足一行时底部留白）。
- 高度变化（底部工具窗开关、分隔条拖动、窗口缩放）后自动重新 fit。

## 实际行为

最后一行（提示符行）约半行被遮挡，无法看到完整内容；PTY 认为该行可见、shell 不会回卷刷新，用户看不到最后一行的输出与当前输入。

## 影响范围

- 所有终端会话标签（中心岛内的 xterm 终端）。
- 影响：最后一行输出 / 提示符 / 当前输入行不可读，交互受阻。

## 相关文件 / 符号

- `frontend/src/components/terminal/XTerminal.vue` — 唯一的 fit 入口：`onMounted` 内 `ResizeObserver → fitAddon.fit()`、初始 `requestAnimationFrame` fit；容器 `.xterminal-container` 带 `padding: var(--space-3)`（6px，防圆角裁字形）。
- `frontend/src/components/shell/EditorIsland.vue` — 中心岛内容区 `overflow-hidden`，超出即被裁。
- `frontend/src/components/shell/AppShell.vue` — 画布级 flex 布局：底部工具窗展开/收起、分隔条拖动都会改变中心岛可用高度。
- `frontend/src/composables/useTerminalManager.ts` — 已确认无 resize 逻辑，fit 全部在 XTerminal.vue 内。

## 建议方案（可选）

先定位再修，重点区分两类根因：

1. **行数多算一行**（fit 用到的可用高度 > 实际可视高度）：
   - 复现后用 devtools 检查 `.xterminal-container` computed height、`term.rows`、`term._core._renderService.dimensions.css.cell.height` 三者的关系；
   - 检查 fit 时机：容器尺寸变化（底部工具窗开关、分隔条拖动、窗口缩放）是否触发 `ResizeObserver` 回调、回调读到的容器高度是否为最终稳定值（必要时 `double rAF` 后再 fit）；
   - 检查 FitAddon 读取的是 `.xterm` 父容器 computed height——确认容器 6px padding 与 `.xterm` 自身 padding 的扣减口径一致。
2. **行数正确但渲染被裁**（fractional 行高 + Webgl 设备像素取整裁掉行底）：对比关闭 `WebglAddon`（canvas 渲染器）后是否仍裁切；若只在 WebGL 下出现，从 canvas 尺寸取整方向排查。

## 解决记录

- 第一轮（反馈「会话在编辑区域最后一行被遮挡，无法显示完整内容。」）：
  - **根因**（经 xterm v6 源码比对确认，两条「行高变化但不重算行数」的失同步路径）：
    1. xterm 在 `fontFamily` / `fontSize` option 变更时同步重测行高（`CharSizeService.measure`），但**不重算行数**；原 `XTerminal.vue` 的字号 / 字体 watch 只改 option 不补 fit。行高变大后 `rows × 新行高 > 容器高度`，最后一行溢出下缘被裁。
    2. dpr 变化（窗口在 Retina / 外接屏间移动）时核心走 `handleDevicePixelRatioChange()` 重测行高，同样不重算行数；且容器 css 尺寸可能不变，`ResizeObserver` 不触发，无任何 refit 时机。
    - FitAddon 0.11.0 与 WebGL 渲染器的稳态换算（`css.cell.height = ceil(测量高×dpr)×lineHeight/dpr`，rows = floor）自洽，排除「行数多算」类根因。
  - **处理**：`frontend/src/components/terminal/XTerminal.vue` —
    - 新增 `scheduleFit()`（双 rAF 后 `fitAddon.fit()`）：字号 / 字体 watch 在改 option 后补一次 fit；
    - 新增 dpr 监听：`matchMedia('(resolution: Ndppx)')` change 时 refit 并跟随新档位重新挂监听，卸载时移除；
    - 新增标签激活 watch 兜底 fit：隐藏期间若发生未触发 RO 的失同步，激活时收敛。
  - **校验**：`pnpm typecheck` 0 错误。
  - **遗留**：待实机验收（本地无 SSH 环境未复现截图场景）。若改字号 / 换屏后仍裁切，按「建议方案」用 devtools 采集 `.xterminal-container` 高度、`term.rows`、`css.cell.height` 三项数据定位下一轮。
- 第二轮（反馈「测试发现终端的最后一行还是显示不完整，有一部分内容被遮挡」）：
  - **根因**（最小复现页 + headless 浏览器 dpr=2 实测定位，非第一轮的字号 / 字体 / dpr 路径）：
    - `.xterminal-container` 全局 `box-sizing: border-box`（global.css reset）下带 `padding: 6px`；CSSOM 规定此时 `getComputedStyle().height` 的 resolved value 是**含 padding 的 border-box 高**。FitAddon 的 `proposeDimensions` 读的恰是这个值，且只减 `.xterm` 自身 padding（为 0）、**永不减父容器的 12px padding** → 可用高度虚高 12px → 行数多算。
    - 实测表现：最后一行常年在 content 底缘以下 2～12px；当「容器总高 mod 行高 < 6px」时 canvas 底缘直接超出容器 border-box 底缘 1～6px，被中心岛 `overflow-hidden` 物理裁掉——与用户「有一部分内容被遮挡」吻合。是否被裁仅取决于窗口高度取值余数（约 6/16 的高度取值中招），与字号 / dpr / 操作时序无关，故第一轮修复无效。dpr=1 环境初次实测未暴露纯属取值巧合（668 mod 16 = 12 > 6）。
    - 遍历验证（rootH 700→710，cellH=16）：`容器高 mod 16` 为 0～5 时裁 1～6px（+6.0→+1.0），≥6 时不裁但仍侵入 padding 区。
  - **处理**：`frontend/src/components/terminal/XTerminal.vue` — 模板内衬一层无 padding 的 `.xterm-host`（`width/height: 100%`）供 xterm 挂载，6px padding 保留在外层 `.xterminal-container`（圆角防裁效果不变）。FitAddon 读到的 `.xterm` 父元素（`.xterm-host`）computed height 即真实可视高度，口径归位；`terminalRef` / ResizeObserver / 右键菜单随之指向内层，fit 逻辑本身未动。
  - **校验**：复现页以同结构在 headless 浏览器 dpr=2 遍历 11 组高度（rootH 700→710），canvas 底缘距容器底缘 -10～-20px、距 content 底缘 -4～-14px，全部为底部留白，零裁切；rows 相应减少 1（如 23→22），符合「行数按可视高度向下取整、不足一行留白」的期望行为。`pnpm typecheck` 0 错误。
  - **遗留**：待实机验收（重点：原遮挡场景打开会话、拖动底部工具窗分隔条 / 缩放窗口后，最后一行提示符完整可见）。
