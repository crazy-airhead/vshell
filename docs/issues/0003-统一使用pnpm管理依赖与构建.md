# ISSUE-0003 — 前端未使用 pnpm 管理依赖与构建（统一使用 npm）

> **编号**：0003　**状态**：🟢 已修复　**严重程度**：⚠️ 一般（工程规范）
> **发现日期**：2026-07-10　**相关任务**：依赖管理 / 前端构建 / 工程规范

## 问题描述

前端（`frontend/`）当前使用 **npm** 管理依赖与构建，仓库内只有 `package-lock.json`，没有 `pnpm-lock.yaml`，`package.json` 也未声明 `packageManager` 字段。但本目录 `README.md` 的「解决记录约定」里校验命令已写成 `pnpm typecheck`，`CLAUDE.md` 的 Development Commands 仍是 `npm run dev / npm run build` —— **实际工具与文档约定不一致**，需要统一改用 pnpm。

## 复现步骤

1. 进入 `frontend/`：
   - `ls package-lock.json pnpm-lock.yaml` → 只有 `package-lock.json`，无 `pnpm-lock.yaml`。
   - `grep packageManager frontend/package.json` → 无该字段。
2. 查看 `CLAUDE.md` → Development Commands 使用 `npm run dev` / `npm run build`。
3. 查看 `../issues/README.md` → 校验约定写的是 `pnpm typecheck`。
4. 结论：npm（实际）与 pnpm（文档约定）混用。

## 期望行为

统一使用 pnpm 管理依赖与编译：`pnpm install` / `pnpm dev` / `pnpm build` / `pnpm typecheck`，仓库内存在 `pnpm-lock.yaml`，`package.json` 声明 `"packageManager": "pnpm@x"`，文档（CLAUDE.md）命令同步更新。

## 实际行为

- 依赖与锁文件走 npm：`frontend/package-lock.json` 存在，无 `pnpm-lock.yaml`。
- `package.json` 未固定包管理器版本。
- 文档校验约定（`README.md`）已写 `pnpm typecheck`，与实际工具冲突。

## 影响范围

- 本地开发 / CI 的依赖安装一致性、可复现性。
- `node_modules` 体积与磁盘占用（npm 扁平 vs pnpm 内容寻址）。
- 多人协作 / 文档与实际命令不符造成的认知成本。

## 相关文件 / 符号

- `frontend/package-lock.json` — npm 锁文件，需替换为 `pnpm-lock.yaml`。
- `frontend/package.json` — 缺少 `packageManager` 字段。
- `build/Taskfile.yml` — **Wails 构建链路**。原通过 `{{.PACKAGE_MANAGER}}` 分发到 `install:frontend:deps:*` / `frontend:run:*` / `frontend:dev:*`。**已重写为 pnpm 硬编码**：三个分发 task 内联为 `pnpm install` / `pnpm run` / `pnpm dev`，删除全部 npm/yarn/bun 子 task 与 `{{.PACKAGE_MANAGER}}` 引用（实测 wails3 alpha2.117 即便仓库只有 `pnpm-lock.yaml` 仍命中 `:npm` 分支，探测不可靠）。
- `build/docker/Dockerfile.cross:177` — Linux 交叉编译镜像内**硬编码** `npm install --silent && npm run build --silent`，未跟随锁文件，需单独评估。
- `CLAUDE.md` — Development Commands 使用 npm 命令。
- `../issues/README.md` — 校验约定已写 `pnpm typecheck`（与本问题存在不一致，需对齐）。

## 建议方案

1. 在 `frontend/` 执行 `pnpm import`（从现有 `package-lock.json` 导出依赖快照）或直接 `pnpm install` 生成 `pnpm-lock.yaml`。
2. 删除 `frontend/package-lock.json` 与 `frontend/node_modules`，重新 `pnpm install` 确认可正常安装。
3. `frontend/package.json` 增加 `"packageManager": "pnpm@<version>"`（用 `pnpm --version` 的实际版本）。
4. 若 Wails/Vite 插件出现依赖找不到，在 `frontend/.npmrc` 评估 `shamefully-hoist=true`（先不默认开，按需）。
5. 更新 `CLAUDE.md` Development Commands 为 pnpm 命令；确认 `../issues/README.md` 约定的 `pnpm typecheck` 与实际一致。
6. **`wails3 build` / `wails3 dev` 链路直接改 Taskfile 硬编码 pnpm**：实测 wails3 alpha2.117 即便仓库只有 `pnpm-lock.yaml`，`CI=true wails3 build` 仍命中 `install:frontend:deps:npm`（探测不可靠）。故不依赖 wails3 探测，直接将 `build/Taskfile.yml` 的 `install:frontend:deps` / `frontend:run` / `dev:frontend` 内联为 `pnpm install` / `pnpm run` / `pnpm dev`，并删除全部 `:npm`/`:yarn`/`:bun`/`:pnpm` 子 task 与 `{{.PACKAGE_MANAGER}}` 分发 —— npm 路径彻底移除，无回退可能。
7. 评估 `build/docker/Dockerfile.cross:177` 的硬编码 npm：若使用 Docker 做 Linux 交叉编译，需同步改为 pnpm（或前置由宿主构建好 `frontend/dist` 走 COPY，避开镜像内重建）。
8. 校验：`pnpm install` + `pnpm build` 通过、`pnpm typecheck` 0 错；`wails3 dev` / `wails3 build` 走一遍（确认构建日志里前端走 pnpm）。
