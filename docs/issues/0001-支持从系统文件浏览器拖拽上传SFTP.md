# ISSUE-0001 — 支持从系统文件浏览器拖拽文件上传到远程服务器

> **编号**：0001　**状态**：🟢 已修复　**严重程度**：⚠️ 一般（实机验证通过，功能本已实现）
> **发现日期**：2026-07-10　**相关任务**：SFTP / 文件传输

## 问题描述

从系统文件浏览器（macOS Finder）把文件**拖拽**到 SFTP 面板的远程文件列表区域，即可上传到当前 SSH 会话的远程目录。

> 调查备注：登记之初曾误判为「后端缺失、前端悬空」，后查 `main.go` 发现后端链路早已完整实现（见「相关文件」）。2026-07-10 实机验证通过，功能正常生效。本条目记录该排查 / 验证结论，非缺陷修复。

## 复现步骤（验证用）

1. 连接一台 SSH 服务器，打开其 SFTP 面板（底部工具 → SFTP）。
2. 打开系统 Finder，选中一个或多个本地文件。
3. 将文件拖向 SFTP 面板的「远程」文件列表区域（带 `id="remote-drop-zone-..."` 的容器）。
4. 松开鼠标。

## 期望行为

拖入远程列表区域时高亮提示，松开后文件上传到当前远程目录（`currentPath`），传输进度通过 `sftp:progress` 事件展示，完成后远程列表自动刷新。

## 实际行为（已验证）

✅ 符合预期：从 Finder 拖文件到远程列表区域，上传正常触发，进度与刷新均正常。

## 影响范围

- SFTP 文件上传的核心交互场景之一，已可用。
- 应用内 local→remote 拖拽（基于指针事件的自定义拖拽）与「选择文件上传」按钮同样可用。

## 相关文件 / 符号

**后端（已实现）**
- `main.go`
  - `EnableFileDrop: true`（约 L90）—— 启用窗口 OS 文件拖放。
  - `win.OnWindowEvent(events.Common.WindowFilesDropped, ...)`（L103-113）：取 `event.Context().DroppedFiles()` 与 `DropTargetDetails()`，`Event.Emit("native:file-drop", { files, targetId: details.ElementID })`。

**前端（已实现）**
- `frontend/src/components/sftp/SFTPPanel.vue`
  - `handleNativeFileDrop`（约 L496）监听 `native:file-drop`，校验 `data.targetId === 'remote-drop-zone-' + connectionID` 后调用 `handleUploadDrop(paths)`。
  - `handleUploadDrop`（L479）逐个 `SFTPUpload(connectionID, localPath, remotePath)`。
  - 远程列表容器（L649）带 `id="remote-drop-zone-<connectionID>"` 与 `data-file-drop-target`。
  - `onMounted`（L582）注册 `Events.On('native:file-drop', handleNativeFileDrop)`。
