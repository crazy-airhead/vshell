# HTTPS 证书管理

左条的「证书管理」图标（盾牌）打开证书面板：通过 SSH 在**远程服务器**上驱动 [acme.sh](https://github.com/acmesh-official/acme.sh)，完成 Let's Encrypt 等 CA 证书的签发、部署与自动续签。vShell 本地只保存「证书任务」，实际证书由服务器上的 acme.sh 管理。

> 验证方式为 **DNS-01**：需要域名 DNS 服务商的 API 凭据（阿里云 / DNSPod / 腾讯云 / Cloudflare，或自定义 acme.sh 插件），无需开放 80 / 443 端口，也支持泛域名。

---

## 1. 面板结构

任务**按连接（服务器）分组**折叠展示，每条任务显示：

- 状态标签：**待签发 / 执行中 / 已签发 / 失败**（失败时附最近一次错误信息）
- 域名（主域名 + 附加域名）
- 到期标签：剩余 N 天 / 即将到期（30 天内，黄色）/ 已过期 / 服务器上不存在
- 测试模式的任务带黄色 `staging` 标签

**到期与续签是两个时间**：证书真实到期时间（「剩余 N 天」）与 acme.sh 的自动续签倒计时（「N 天后自动续签」）分开显示——acme.sh 会提前续签（约在证书有效期的前 1/3 窗口内），因此续签倒计时总是短于到期倒计时，二者不可混为一谈。

| 操作 | 位置 | 说明 |
|------|------|------|
| 刷新远端状态 | 分组标题右侧 | 重新读取服务器 `acme.sh --list`，同步远端实际状态 |
| 立即签发 / 续签 | 行内按钮 | 待签发任务执行签发，已签发任务执行续签 |
| 日志 | 行内按钮 | 查看该任务最近一次操作的完整日志 |
| 编辑 | 行内按钮 | 修改域名 / DNS 凭据 / 部署配置 |
| 从服务器移除 | 行内按钮 | 让服务器上的 acme.sh 移除该证书，并删除本地任务 |
| 删除任务 | 行内按钮 | 仅删除本地任务记录，服务器上的 acme.sh 仍继续管理该证书 |

## 2. 签发证书向导

点击「签发证书」进入四步向导：

### 第 1 步 · 服务器

- 选择目标连接（给哪台服务器签证书）
- **ACME 账户邮箱**：首次在该服务器安装 acme.sh 时用于注册 CA 账户，输入后会被记住，之后不再填写
- 打开向导时自动检测服务器环境：acme.sh 是否已安装、自动续签 cron 是否存在、curl 是否可用；未安装时可在本步一键安装

### 第 2 步 · 域名与 DNS

| 字段 | 说明 |
|------|------|
| 任务名称 | 默认取主域名 |
| 主域名 | 如 `example.com` |
| 附加域名 | 每行一个，支持泛域名（如 `*.example.com`） |
| DNS 服务商 | 阿里云 / DNSPod（传统 Token）/ 腾讯云（SecretId + SecretKey）/ Cloudflare / 自定义 |
| 凭据变量 | 按所选服务商动态渲染表单；选「自定义」需填 acme.sh 插件名（`dns_xx`，见 acme.sh dnsapi 文档）与凭据键值对 |

### 第 3 步 · 部署

| 字段 | 说明 |
|------|------|
| 部署证书到服务器路径 | 开启后填写证书目录、私钥文件名、证书链文件名，签发成功后自动拷贝部署 |
| 重载命令 | Nginx / Apache / Caddy 预设或自定义（如 `nginx -s reload`）；「不重载」则跳过 |
| 高级选项 | 密钥类型（ECC P-256 默认 / RSA 2048）、DNS 传播等待秒数（默认 120）、**测试模式** |

> **测试模式（staging）**：使用 CA 测试环境签发，用于首次跑通流程，避免触发 Let's Encrypt 正式环境的频率限制；跑通后关闭测试模式，重新签发正式证书。

### 第 4 步 · 签发

自动按阶段执行并实时输出日志：**检测环境 → 安装 acme.sh（如需）→ 申请证书 → 部署证书 → 检测定时任务 → 完成**。日志区固定高度内滚动，右上角可一键复制；失败后可直接重试。

## 3. 凭据安全

- DNS API 凭据以 AES-256-GCM 加密入库，**永不明文回传前端**；需要核对已存凭据时走专门的「查看已存凭据」入口
- 签发时凭据经 SFTP 写入服务器上的**临时 env 文件**（权限 600，签发命令结束时自删），不会进入 shell 历史
- 详见[数据存储与加密](../dev/storage-crypto.md)

## 4. 续签机制

- 续签由**服务器上的 cron 每日执行**，无需保持 vShell 在线
- vShell 内手动续签刻意走 `--issue --force` 而非 `--renew`：`--renew` 会重放服务器上旧配置里的插件与凭据，在 vShell 里更换过 DNS 服务商或凭据后不会生效；`--issue --force` 则始终使用**当前任务保存的凭据**
- 在 vShell 中更换 DNS 服务商 / 凭据后，执行一次「立即续签」即可让服务器上的续签配置同步为新凭据

## 5. 日志

- 每次操作的日志**持久化保存在本地任务上**，重开日志窗口不丢
- 每次操作开始会先**清空服务器侧 acme.sh 日志**再执行，日志窗口看到的即是本轮输出
- 也可通过「服务器 acme.sh 日志」入口直接查看服务器上 acme.sh 自身的日志文件

## 6. 删除与移除的两种语义

| 操作 | 本地任务 | 服务器证书 |
|------|----------|------------|
| 删除任务 | 删除 | 保留，acme.sh 仍继续管理并自动续签 |
| 从服务器移除 | 删除 | acme.sh 移除该证书（停止续签）；**已部署的证书文件保留** |

## 7. 当前边界（如实说明）

- 仅支持 DNS-01 验证（无 HTTP / 文件验证）
- 目标服务器需为类 Unix 环境且可安装 acme.sh（依赖 curl 与 cron）
- vShell 中没有签发过程的「取消」按钮；应用重启后，上次被中断的「执行中」任务会自动复位，可重新发起
